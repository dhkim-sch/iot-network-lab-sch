# 홈페이지 절제형 모션 설계

## 1. 목적

현재의 정적 연구실 홈페이지에 전문성과 가독성을 해치지 않는 시각적 움직임을 추가한다. 사용자가 페이지를 내려가며 주요 섹션과 정보를 자연스럽게 인지하도록 돕되, 학술 정보 탐색을 방해하는 반복 애니메이션이나 과도한 장식은 사용하지 않는다.

이 문서는 구현 방향만 정의한다. 홈페이지 코드와 배포본은 이 단계에서 변경하지 않는다.

## 2. 결정 사항

- 시각 방향: 절제된 움직임
- 적용 범위: 전체 페이지의 섹션 제목과 주요 카드
- 재생 정책: 각 요소가 처음 화면에 들어올 때 한 번만 재생
- 구현 방식: 외부 라이브러리 없이 CSS와 `IntersectionObserver` 사용
- 긴 목록: publication 및 alumni 항목별 애니메이션 대신 그룹 단위 애니메이션 사용
- 접근성: `prefers-reduced-motion` 사용자는 애니메이션 없이 최종 상태를 즉시 확인

## 3. 목표와 비목표

### 목표

- 첫 화면과 스크롤 경험에 가벼운 생동감을 추가한다.
- 제목, 카드, 통계 등 정보 계층을 움직임으로 보조한다.
- 기존 publication 검색·필터, 내비게이션 및 콘텐츠 렌더링을 그대로 유지한다.
- JavaScript 오류나 미지원 브라우저에서도 모든 콘텐츠가 보이도록 한다.
- 모바일과 저성능 기기에서도 부드럽게 작동하도록 한다.

### 비목표

- 반복 재생되는 배경 애니메이션
- 패럴랙스, 커서 추적, 파티클 또는 블러 전환
- 페이지 전환 애니메이션
- 외부 애니메이션 라이브러리 도입
- publication, member 또는 기타 콘텐츠 데이터 변경
- 이번 계획 단계에서의 실제 코드 수정이나 배포

## 4. 접근법 비교

### 선택: CSS + IntersectionObserver

기존 순수 HTML/CSS/JavaScript 구조에 가장 잘 맞는다. 브라우저 지원 범위가 넓고, 애니메이션 실행 시점과 한 번만 재생하는 정책을 명확하게 제어할 수 있다. 추가 네트워크 요청이나 번들 크기 증가가 없다.

### 대안 1: CSS Scroll-driven Animations

선언형 코드가 가능하지만 브라우저 지원과 동작 일관성이 상대적으로 낮다. 이번 사이트에 필요한 단순한 최초 노출 애니메이션에는 이점이 크지 않다.

### 대안 2: GSAP 또는 AOS

복잡한 타임라인을 빠르게 만들 수 있지만 외부 의존성과 유지관리 비용이 추가된다. 본 설계의 작은 이동과 페이드 효과에는 과도하다.

## 5. 모션 원칙

- 정보보다 움직임이 먼저 눈에 띄지 않아야 한다.
- 이동 거리는 기본 `12px` 이내로 제한한다.
- 기본 등장 시간은 약 `450–500ms`로 한다.
- 요소 간 시차는 `60–70ms`로 하고 총 지연은 `280ms`를 넘지 않도록 제한한다.
- 이징은 빠르게 시작해 부드럽게 멈추는 곡선을 사용한다.
- 레이아웃을 다시 계산하는 속성 대신 `opacity`와 `transform`만 애니메이션한다.
- 자동으로 반복하거나 사용자의 스크롤을 가로채는 움직임은 사용하지 않는다.

## 6. 구성 요소별 동작

### Hero

- kicker, 제목, 소개 문구, 버튼을 순서대로 짧게 페이드업한다.
- 요소 간 시차는 약 `70ms`로 한다.
- Hero 이미지에는 지속적인 부유 효과나 패럴랙스를 적용하지 않는다.
- 공지 카드가 Hero와 함께 보이면 마지막 순서로 한 번 등장시킨다.

### Quick stats

- 통계 블록은 하나의 행으로 페이드업한다.
- `51`, `11`, `34`, `4`와 같은 값은 화면에 처음 들어올 때 약 `700ms` 동안 정수 카운트업한다.
- 최종 값은 기존 데이터 배열에서 계산된 값을 사용하며 별도로 하드코딩하지 않는다.
- 애니메이션 감소 설정이나 미지원 환경에서는 최종 값을 즉시 표시한다.

### Section headings

- About, Research, Publications, Members, Join, Contact의 kicker·제목·설명 묶음을 하나의 단위로 페이드업한다.
- 각 섹션에서 최초 한 번만 재생한다.
- About의 소개문과 프로필 패널, Join의 안내 패널도 각각 하나의 콘텐츠 그룹으로 등장시킨다.

### Cards and grids

- Research 카드, 현재 재학생 카드, contact 블록은 같은 행 안에서 `60ms` 간격으로 순차 등장한다.
- 카드 수가 많은 경우 지연을 최대 `280ms`에서 고정해 마지막 항목이 지나치게 늦게 나타나지 않도록 한다.
- hover가 가능한 장치에서는 카드가 최대 `2px` 올라오고 그림자가 조금 선명해진다.
- 터치 장치에는 hover 이동을 강제하지 않는다.

### Long lists

- Publications는 각 journal, conference, patent 섹션 단위로만 등장시킨다.
- Members의 긴 alumni 목록도 그룹 단위로만 등장시킨다.
- 검색이나 필터 변경으로 다시 렌더링되는 publication 결과에는 등장 애니메이션을 다시 적용하지 않는다. 결과는 즉시 갱신해 탐색 흐름을 방해하지 않는다.

### Navigation and footer

- 기존 활성 메뉴 표시와 부드러운 스크롤은 유지한다.
- 내비게이션과 footer에는 진입 애니메이션을 추가하지 않는다.

## 7. 기술 구조

### CSS 모션 토큰

`styles.css`에 거리, 지속 시간, 시차 및 이징을 CSS 사용자 정의 속성으로 정의한다. 공통 reveal 상태, visible 상태, 카드 hover 상태를 이 토큰으로 구성해 섹션별 편차를 줄인다.

콘텐츠는 기본 상태에서 항상 보인다. JavaScript가 `IntersectionObserver` 사용 가능 여부와 모션 감소 설정을 확인한 뒤 문서 루트에 모션 활성화 클래스를 추가한 경우에만 reveal 대상의 초기 투명·이동 상태가 적용된다.

### Reveal controller

`script.js`에 다음 책임만 갖는 작은 모션 초기화 단위를 추가한다.

1. 모션 실행 가능 여부를 확인한다.
2. 초기 렌더링이 끝난 뒤 reveal 대상을 수집한다.
3. 그리드 항목에 제한된 stagger 값을 지정한다.
4. 요소가 viewport에 진입하면 visible 클래스를 추가한다.
5. visible 상태가 된 요소를 즉시 관찰 해제한다.

기존 내비게이션용 `IntersectionObserver`와 목적이 다르므로 별도의 Observer를 사용한다. 내비게이션 Observer는 현재 섹션을 계속 추적해야 하지만 모션 Observer는 한 번 실행한 뒤 해제되어야 한다.

### Count-up controller

통계 값은 `renderStats`가 계산한 최종 값을 기준으로 한다. 통계 영역이 처음 노출되면 `requestAnimationFrame`으로 `0`부터 최종 정수까지 보간하고, 마지막 프레임에서 반드시 원래 최종 문자열을 다시 설정한다.

모션 감소 설정, 탭 비활성화 또는 실행 중 오류가 발생하면 즉시 최종 값으로 복구한다. 별도 `aria-live` 영역은 만들지 않아 중간 숫자가 보조 기술에 반복 안내되지 않도록 한다.

## 8. 초기화 순서와 데이터 흐름

1. 기존 renderer가 notices, stats, profile, research, publications, members, contact를 만든다.
2. 기존 내비게이션과 publication 컨트롤 이벤트를 연결한다.
3. 마지막에 모션 초기화를 호출한다.
4. 모션 초기화가 현재 DOM의 대상만 등록한다.
5. Observer가 최초 진입을 감지하고 visible 상태를 적용한 뒤 해당 대상을 해제한다.
6. 이후 publication 검색·필터 결과는 모션 등록 없이 즉시 렌더링한다.

## 9. 접근성과 실패 대응

- `prefers-reduced-motion: reduce`에서는 전환, 이동, 카운트업을 모두 비활성화한다.
- 키보드 focus 스타일은 hover 모션과 별개로 항상 명확하게 유지한다.
- JavaScript가 비활성화되거나 오류가 발생해도 콘텐츠는 기본적으로 보인다.
- `IntersectionObserver`가 없는 환경에서는 모션 활성화 클래스를 추가하지 않는다.
- 모션 초기화는 기존 콘텐츠 렌더링 뒤에 독립적으로 실행하고 `try/catch`로 격리한다. 초기화가 실패하면 모션 활성화 클래스를 제거해 모든 콘텐츠를 즉시 보이는 상태로 복구한다.
- 애니메이션 중에도 링크, 버튼, 검색창의 클릭 영역과 문서 흐름을 변경하지 않는다.

## 10. 성능 기준

- 외부 라이브러리와 추가 네트워크 요청이 없어야 한다.
- 애니메이션 속성은 `opacity`와 `transform`으로 제한한다.
- 하나의 reveal Observer로 모든 모션 대상을 관리한다.
- 관찰 대상은 재생 직후 해제한다.
- 긴 목록의 개별 항목을 관찰하지 않는다.
- 모바일에서 스크롤 중 눈에 띄는 프레임 저하나 레이아웃 이동이 없어야 한다.

## 11. 검증 계획

### 기능 검증

- Hero, 통계, 섹션 제목 및 주요 카드가 최초 진입 시 한 번만 등장하는지 확인한다.
- 위로 스크롤한 뒤 다시 방문해도 애니메이션이 반복되지 않는지 확인한다.
- 통계 최종 값이 현재 데이터 기준 `51`, `11`, `34`, `4`로 정확한지 확인한다.
- publication 검색과 유형 필터가 기존처럼 즉시 작동하는지 확인한다.
- 모바일 내비게이션과 활성 섹션 표시가 유지되는지 확인한다.

### 접근성 검증

- 운영체제의 Reduce Motion 설정에서 모든 콘텐츠와 최종 통계가 즉시 표시되는지 확인한다.
- 키보드만으로 모든 링크, 버튼 및 검색창을 사용할 수 있는지 확인한다.
- 애니메이션 전후에 의미 있는 콘텐츠 순서와 접근성 트리가 바뀌지 않는지 확인한다.

### 시각 및 성능 검증

- 데스크톱과 모바일 너비에서 레이아웃 이동이 없는지 확인한다.
- 빠른 스크롤에서도 요소가 빈 상태로 남지 않는지 확인한다.
- hover가 없는 터치 환경에서 카드가 들뜬 상태로 고정되지 않는지 확인한다.
- 브라우저 콘솔 오류가 없고 기존 정적 자산 외 추가 요청이 없는지 확인한다.

## 12. 완료 기준

- 페이지 전체가 이전보다 생동감 있게 느껴지되 학술 정보의 가독성이 유지된다.
- 모든 모션은 최초 노출 시 한 번만 재생된다.
- 반복 배경 효과와 과도한 이동이 없다.
- 모션 감소 사용자와 미지원 환경에서 기능 저하 없이 콘텐츠를 이용할 수 있다.
- 기존 검색, 필터, 내비게이션 및 데이터 기반 통계가 회귀 없이 동작한다.
